# 润网表单在线验收

此目录将现有表单页面、分类、匹配规则和 Word 样表接入独立的线上验收环境。报价和审核维持骨架入口。只填写虚构资料。

登录私有站点后选择模拟身份（员工 A、员工 B、模板管理员）。每一位登录者拥有独立的验收空间。模拟身份用于验证记录隔离和管理权限，不是正式公司的员工账号。已签发的会话 8 小时后过期，重新进入同一身份后仍可查询原记录。文件下载在服务器端复核身份和归属。

## 验收

1. 选员工 A，再选商务专线、测试版（不带语音）、新装及一个测试套餐。匹配模板后，用虚构样例补全空白栏，确认生成 Word。
2. 查看历史记录，重新下载。切换员工 B，检查无法看到员工 A 的记录。
3. 选择模板管理员，下载基础样表、上传新版本、启用它；返回员工 A 验证多候选需要人工选择。基础上传使用带占位符的简表。授权模板管理员也可在“智能导入 Word”中上传 100M 智云上海专线基础版（FTTR-B，不带语音）原表，确认三档资费、保存并启用，再分别生成现金与托收申请。

## 装配和更新私有站

需要 Node.js 22.13+、Python 3.9+，更新已有站点还需要其 Git 历史。在本仓库根目录运行以下命令安装锁定版本的 Word 处理依赖。

```sh
npm ci --prefix online --ignore-scripts
```

全新 Vinext Sites starter 使用下列命令。装配脚本会复制站点使用的 XML 和 ZIP 代码及许可证。

```sh
node online/prepare-site.mjs /绝对路径/空白的验收站点工程
```

已有私有站点使用其 Git 源码与上一次同步本仓库时的**共同基线提交**。如果双方都改过同一文件，脚本会列出冲突并在写入前停止。核对后，将合并好的文件按站点内的相对路径放在独立目录中，再传入 `--overlay`。现场原表、客户资料和凭据留在私有环境。

```sh
node online/prepare-site.mjs /绝对路径/私有站点工程 --update-from <共同基线提交>
node online/prepare-site.mjs /绝对路径/私有站点工程 --update-from <共同基线提交> --overlay /绝对路径/核对后的合并文件
```

在目标工程中安装其 starter 依赖，生成增量迁移并执行全套测试。

```sh
npm run db:generate
node --test tests/*.test.mjs
npm run build
```

用同一 Site 的发布流程应用 D1 增量迁移并绑定原 R2，维持原站点访问范围。已有站点的迁移历史必须随源码保留。

此部署适配器依赖托管平台验证并注入的用户身份。不要将未经认证的 HTTP 服务直接暴露在公网并信任浏览器自报的身份头。D1 保存权限会话、模板目录和记录，R2 保存私有文档。正式客户上线需另行确认员工身份、模板和资费。
