# 结构与范围

主界面：业务报价、表单填写、手续审核。当前重点建设表单填写，其他两个板块保留入口。

表单填写：表单生成、表单历史记录、套餐模板管理。

表单生成和模板管理共享分类：业务名称 → 业务版本 → 业务属性。初始名称为IPMAN、精品专线、商务专线、智能专线，来自服务端并允许扩展。属性为新装、移机、变更、拆机。新仓库不自动导入旧模板。

表单生成页合并业务选择与客户信息。优先实现商务专线／新装／不带语音：企业全称、安装地址、账单地址、套餐和资费、经办人完整姓名、手机号、身份证号、E-mail、付款方式（现金／托收）；托收时银行账号、开户银行必填。

## 后续流程（尚未实现）

报价确认 → 带入已确认的套餐及资费 → 客户核对与模板匹配 → 补充必要信息 → 确认生成 → 提交手续审核 → 通过或退回补充。

通过业务申请ID连接模块。报价规则、审核角色和材料要求待确认，不擅自假设审批规则。

## 数据实体规划（尚未建表）

| 实体 | 主要责任 |
| --- | --- |
| 业务分类与版本 | 稳定ID、名称、归属、适用时间、启用状态 |
| 资费档位 | 套餐、金额、周期、带宽、优惠、语音属性 |
| 模板 | 分类/版本/属性、语音属性、模板版本、条件、映射、状态 |
| 业务申请 | 客户资料、确认的套餐资费、办理阶段、创建人和时间 |
| 生成记录 | 申请、模板及版本快照、创建人、生成时间、状态、文件引用 |
| 审核记录 | 申请、审核人、结果、原因、时间 |

生成次数和申请办理状态分开记录，重复生成不能算新增业务。数据库结构后续通过迁移管理。

## 匹配原则

客户身份证、地址、银行资料用于填表，不用于猜测套餐。依据确认的业务、版本、属性、语音、套餐及资费元数据匹配。禁止仅凭价格、最高ID、最新模板或AI置信度选模。

结果分为unique、ambiguous、not_found、conflict。多候选、无候选、冲突和必填不足均阻止生成，提示员工选择或补充。员工选定后后台复核。模板仍要求的行业、邮编、线数、客户经理等资料按需补充，不编造或擅自取消必填。

## 当前边界

仅页面导航、统一分类、明确空列表。没有数据库或业务提交接口，客户输入禁用。正式使用前必须实现认证、权限、持久化、后台校验及文件验证。
