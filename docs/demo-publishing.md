# 共享演示网页自动发布

固定入口：https://runwell-demo.shipstatic.com/#/forms

## 两人的日常流程

各自在开发分支上传代码，创建合并申请，目标选 `feature/project-skeleton`。合并申请自动运行检查，不改变公共网页。任意一人的代码合并到该共享分支后，GitHub Actions 自动检查、构建演示包、发布并更新固定入口。刷新同一网址即可看到合并后的界面，无需保持本机或 Codex 开启。

发布通常需要几分钟，以仓库 Actions 中的 `Update shared demo` 结果为准。检查或构建失败时不发布，固定入口保留上一版。发布串行进行，防止旧任务覆盖新版本。

## 首次连接发布账号

1. 用拥有 `runwell-demo.shipstatic.com` 的 ShipStatic 账号打开 https://my.shipstatic.com/api-key ，复制已有 API key，不要重置它。
2. 打开仓库 Settings → Secrets and variables → Actions → New repository secret，名称填 `SHIP_TOKEN`，值填上述 API key，保存。不要把密钥发到聊天、提交、Issue 或截图。
3. 在 Actions 中重新运行失败的共享分支发布任务。成功后检查固定网址和 `/version.json` 的 commit 是否对应本次合并。

固定域名切换需要 API key；仅能上传的 deploy token 不支持域名切换。账号连接插件的凭据不会自动提供给 GitHub。

## 当前演示范围

固定 Demo 打开即用。表单填写支持识别客户回复、补齐必填、匹配测试套餐模板、生成和下载 Word、查询历史、导入兼容 DOCX 模板及启停。实际字段和必填条件以表单模块及所选样表为准。报价和审核仍只保留入口。

Word 预览会先从文件名和套餐区提取网速、套餐名、版本、语音和折扣。识别资料与转换分开；未核对的版式只显示资料，不生成 Word。

可选实时 AI：将 `online/template-ai.mjs` 部署为独立 HTTPS Worker，配置 `DEMO_ORIGIN=https://runwell-demo.shipstatic.com`、服务端 Secret `AI_API_KEY`（DeepSeek）和 `DEMO_AI_TOKEN`（至少 32 字符的随机验收口令）。上线前在网关配置请求限额并在模型账号设置用量上限；Worker 内限流只作用于单个实例。然后在 GitHub Actions 仓库变量设置 `DEMO_AI_ENDPOINT=https://你的域名/template-ai`。未配置地址时不会开放网络连接。配置后，管理员输入验收口令并主动请求 AI，只发送套餐摘要，原 Word、文件名原文与客户填写区不发送。AI 建议不改变模板版式或自动入库。

「设置」需为同一 Worker 绑定专用 KV 命名空间 `INTEGRATION_SETTINGS`，并设置两个独立的随机 Secret：`SETTINGS_ADMIN_TOKEN` 和 `SETTINGS_ENCRYPTION_KEY`（各至少 32 字符，不复用 AI 验收口令）。设置页用管理员口令认证，凭据加密保存，只返回配置状态。设置页保存的 AI Key 优先于 `AI_API_KEY` 环境备用值；企查查仅配置 API Key 和 Secret Key，暂未发起查询。KV 的跨节点同步可能有延迟。

在「套餐模板管理 → 智能导入 Word」拖入智云上海专线基础版（FTTR-B）不带语音原表或已转换模板（支持 5 月版和 10 月 21 日版，按版式分别入库）。页面列出识别到的月付、年付和两年付资费；每个版式只保存一份模板，员工在生成表单时选择资费。重复导入同一版式不会覆盖原记录。新模板默认停用，核对后在目录启用。模板保留原版式和空框，生成时按所选资费与客户选项涂黑对应方框。其他版式无法确认字段位置时会拒绝导入，可使用原有手动上传入口。

只使用虚构客户和测试模板。录入内容、导入的模板和生成文档在浏览器内处理；模板、历史和文件保存在当前浏览器。不同设备和浏览器配置不共享，刷新后可继续使用，清除站点数据会删除本地记录。支持具备 IndexedDB、Web Locks 和 WebAssembly 的新版浏览器。

模板目录可逐个删除启用或停用的模板（含内置样表），需二次确认。删除仅影响当前浏览器，刷新或会话更新不会恢复已删除的样表。智能导入自动创建的套餐，如果已没有其他模板，也会从套餐列表移除。已生成的历史 Word 文件仍可下载。
可通过「清除内置测试套餐」一次性移除当前浏览器的内置样表；已有自定义模板和历史文件保留。

本地构建：`npm ci --prefix demo --ignore-scripts`，`node --test demo/runtime.test.mjs`，`node demo/build.mjs`。构建需要 Node 24 和 Python 3；输出 `dist/demo-interactive`，`version.json` 的模式为 `browser-demo`。用本机静态服务器打开产物进行验收；浏览器不可直接打开文件路径。旧只读构建保留供回退。

交互演示复用 oneaskq 的验收页面、匹配、校验与 Word 渲染代码。`demo/` 负责静态打包和本地存储；真实客户数据、正式模板和员工权限仍由正式系统管理。本机验收模式和私有托管模式不受影响。

## 维护与回退

自动发布配置位于 `.github/workflows/deploy-demo.yml`。只识别共同仓库的共享骨架分支，不自动合并开发分支或其他仓库。需要迁移共享分支时同步修改工作流和此文档。

回退请向共享分支提交 revert，再通过同一流程发布。不要重新运行旧提交来覆盖新版本。测试用临时数据库与生成文件会在检查后清理；不读旧项目资料。

官方说明：https://docs.shipstatic.com/action ，https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets 。

## 已核验原表的统一生成流程

演示包内置八份已核验样表；管理员也可在「套餐模板管理 → 智能导入 Word」上传未修改的空白原表，确认导入后在目录启用。100M／200M、智云护航 AI 及外地公司担保书按文件哈希核验，文件名不决定版式。同一版式只建一份模板，月付、年付和两年付共用该模板。

员工统一进入「表单生成」，选择商务专线、业务版本、新装及套餐资费；办理担保书时选「外地公司担保书」。匹配启用的模板后填写所需资料，再点「确认生成 Word」。申请人职务默认 IT、企业规模默认 31–80 人、计算机数量默认 16–40 台，均可修改；经办人和信息安全责任人职务默认跟随申请人。账单地址默认跟随安装地址，选择不同后单独填写；已核验套餐原表会在“其他”栏写入实际地址。页面可识别地址中明确标注的邮编，没有可靠标注时需手填；传真可留空。经办人职务、信息安全责任人、业务用途及申请日期等默认值收在「修改默认信息」中，必填资料缺失时单独提示；账单地址相同时复用安装邮编。

客户资料、语音实名资料和企业信息默认收起。识别客户回复或生成时，待补充的资料会在页面上提示；可展开对应资料查看或修改全部内容。企业查询入口位于客户回复下方，仍只提供虚构样例，企查查正式接口尚未接入。

六份内置 100M/200M 及两份 AI 样表分别提供经该原表核验的业务选项。纯新装为默认值，其余业务由员工按客户确认结果选择；需要的数量、号码和附加信息必须填齐。未选择的项目不自动订购。旧版转换模板只覆盖其已核验的部分选项；其他导入版式或未映射栏目按页面提示手工核对，不假设所有模板均有相同业务。八份内置样表的身份证、邮箱和电话栏在生成副本中按对应版式扩宽；原模板不变。生成后可从历史记录下载，签章仍需人工完成。

既有智能导入流程中，受支持的 FTTR-B 原表在生成时要求填写申请日期，授权委托书签署日期仍留空。PR #8 的 AI 识别、凭据设置与现有模板和历史的存储方式继续沿用。

原表测试可设置环境变量 RUNWELL_REVIEWED_FIXTURES 指向经核验的空白原表目录，再运行 `node --test demo/runtime.test.mjs demo/reviewed.test.mjs`。目录仅用于本地校验，不提交原表。生成测试核对 Word 的字段和勾选，发布前仍需在 Word 中检查最终排版。
