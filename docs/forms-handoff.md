# 表单填写板块交接给 oneaskq

仓库：https://github.com/cxh12357-source/-runwell-form-v2

## 分工与现状

项目负责人仅负责业务报价、表单填写、手续审核三大板块的公共骨架。oneaskq负责表单填写完整板块，包含前后端、数据、模板及测试。业务报价和手续审核暂不开发。

骨架交付分支为feature/project-skeleton。oneaskq先拉取此分支，再从它创建feature/forms-workspace进行开发；骨架合并main后，同步最新main。任务指派状态以GitHub Issue为准，本文档记录交付要求。

已完成：表单生成、历史记录、套餐模板管理的页面布局，统一分类只读接口，空列表接口。客户字段禁用，未实现登录、保存、数据库、套餐匹配、Word生成或审核。不得把骨架当成已实现的业务功能。

## oneaskq负责的范围

- frontend/modules/forms.js及后续拆分的表单组件。
- backend/modules/forms/及其持久化、匹配、生成等业务模块。
- 表单领域的测试、数据库迁移、字段及模板配置文档。
- 表单生成、表单历史记录、套餐模板管理三个子模块的完整交付。

共享路由frontend/app.js、全局样式frontend/styles.css、backend/app.mjs、分类模块、package.json等如需调整，在合并申请中注明；变更接口先更新docs/api.md并与骨架负责人协调。

## 业务要求

1. 生成和模板管理统一分类：业务名称 → 业务版本 → 业务属性。初始业务为IPMAN、精品专线、商务专线、智能专线，支持扩展；属性为新装、移机、变更、拆机。
2. 先完成商务专线／新装／不带语音。业务选择与客户填写合并为一步，字段为企业全称、安装地址、账单地址、套餐和资费、经办人完整姓名、经办人手机号、身份证号、E-mail、付款方式（现金／托收）。托收时银行账号和开户银行必填。
3. 依据已核实的套餐、资费周期、带宽、版本及语音属性等确定性匹配。唯一匹配时显示模板及依据；多候选、无候选、信息不足或冲突时提示选择或补充，禁止猜测、仅凭金额选模或静默取最新模板。最终生成必须后台复核。
4. 模板仍需要的其他资料按需提示，不编造、不随意取消必填；填写的账单地址及银行资料必须真正映射到输出文件。
5. 历史记录保留业务分类、模板版本、创建人、时间、状态，并实现真实查询和权限控制。模板管理支持分类、版本、启停、字段映射及安全上传。
6. 保留旧项目和生产数据，核实后再设计迁移，不自动导入未知归属数据。运行数据、真实客户资料及密钥不得提交。
7. 正式后端、数据库、登录及权限方案先与骨架负责人确认，再实现；当前Node本地预览服务不代表正式方案已确定。

## 建议交付顺序

确认接口和数据结构 → 套餐/模板目录 → 信息填写及条件必填 → 匹配与歧义提示 → Word生成 → 历史记录和权限 → 联合验收。

## 验收

- 明确套餐唯一匹配；重复价格不误选；多候选、无候选、冲突和停用模板均正确处理。
- 托收缺少任一银行字段时阻止生成；现金不误用旧银行信息。
- 完整姓名、账单地址、开户银行和账号进入正确Word位置，勾选准确、无残留占位符、版式可核对。
- 历史记录为真实生成记录；员工不可越权读取他人资料或管理模板。
- 页面导航及公共骨架不被破坏；测试使用独立数据库和虚构客户。

oneaskq在feature/forms-workspace等独立分支开发，提交Pull Request供项目负责人验收。未经单独指示不部署。
