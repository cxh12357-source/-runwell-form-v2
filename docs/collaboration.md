# 双人协作

| 负责人 | 范围 | 首批任务 |
| --- | --- | --- |
| 项目负责人 cxh12357-source | 整体骨架、主导航、公共配置、启动入口、公共接口规范 | 搭建三大板块入口与模块边界，不负责表单填写业务实现 |
| oneaskq | 表单填写板块前后端及相关测试 | 表单生成、历史记录、套餐模板管理；客户填写、套餐匹配、条件必填、Word输出与记录 |
| 双方协商 | 公共接口、分类、依赖、数据库与权限方案 | 修改公共模块前确认接口和影响范围 |

oneaskq的具体交接范围见forms-handoff.md。表单页面和服务端业务由同一负责人交付，不再按前后端拆给两人。主导航、全局样式和启动配置由骨架负责人维护，oneaskq若需修改这些文件，应在合并申请中单独说明。同一份Word模板由一人维护。

每人独立克隆、独立分支、独立开发数据库。开工前同步主分支并检查已有改动。任务应包含范围、接口和验收条件。

完成后检查、推送自己的分支、创建Pull Request，另一人审核并在测试环境验收后合并。不得强制推送覆盖他人代码，不直接推送main。合并不等于正式发布。

完整工作台以 `main` 为准。oneaskq 在 `feature/oneaskq-forms` 开发表单，其他开发从 `main` 创建独立分支，再通过合并申请提交。原 `feature/project-skeleton` 保留历史。运行数据库、真实客户附件、生成文件和密钥不进入Git，数据库结构通过迁移文件同步。

共享演示网页从 `main` 自动构建和发布，合并申请只检查。两人合并后的界面共用固定网址，流程、账号连接和展示范围见demo-publishing.md。自动发布不代表正式后台上线。

下一轮：骨架负责人交付公共结构；oneaskq按交接清单完成表单板块。报价、审核目前只保留入口，负责人尚未分配。旧数据归属不清时标记待确认。
